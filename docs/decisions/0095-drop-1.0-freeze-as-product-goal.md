# ADR 0095: Drop the 1.0 freeze as the product goal

- Status: Accepted
- Date: 2026-11-20
- Supersedes: [ADR 0086](0086-supported-1.0-core-contract.md)
  (freeze-as-identity only; 0086 remains the historical freeze record,
  including the receipt fields amended by
  [ADR 0090](0090-receipt-evidence-and-policy-binding.md)).
- Resolves: [#799](https://github.com/Sannrox/rusui/issues/799).
- Related: [ARCHITECTURE.md](../../ARCHITECTURE.md) (product contract;
  this ADR drops freeze-as-identity).
- Discussion: none. GitHub Discussions are disabled. Merging with this
  status is the acceptance act.

## Context

[ADR 0086](0086-supported-1.0-core-contract.md) froze
[ARCHITECTURE.md](../../ARCHITECTURE.md) as a 1.0 product identity. That
split the product into a supported 1.0 core and an excluded list that
could not become the product without a later freeze-class ADR. GitHub
Issues already carry the backlog. Operators and builders paid a second
decision at every track: is this 1.0, or post-1.0.

[#141](https://github.com/Sannrox/rusui/issues/141) closed as that freeze.
[#146](https://github.com/Sannrox/rusui/issues/146) remains a
numbered-release quality bar (independent self-hosting), not this lift.
The freeze was accidental product state. Deleting it as identity leaves
one contract and one backlog.

## Decision

1. [ARCHITECTURE.md](../../ARCHITECTURE.md) describes shipped behavior
   and admitted work. GitHub Issues are the backlog. There is no 1.0
   freeze as product identity.
2. This ADR supersedes ADR 0086's freeze-as-identity. ADR 0086 remains
   the historical freeze record. Receipt fields stay as
   [ADR 0090](0090-receipt-evidence-and-policy-binding.md) amended them.
3. A numbered release remains [#146](https://github.com/Sannrox/rusui/issues/146)
   and still requires independent self-hosting. That is a release quality
   bar, not the product identity. This change does not close #145, #143,
   or #146.
4. Live close, merge, land, and unnamed GitHub writes stay unauthorized.
   Live comments remain policy `comment` only. Repair stays off until
   policy sets it.
5. Deferred ADRs (0033, 0035, 0036, 0037, 0039, 0042, 0043, 0062, and
   peers) stay in force until a later accepted ADR adopts that track.
   Lifting the freeze does not implement those tracks and does not
   silently reverse those ADRs.
6. Current supported topology (same-commit `rusui` and `rusui-runner`,
   one host runner, Docker or Podman CLI, digest-pinned guest image,
   default guest shikigami ACP, SQLite WAL, loopback) remains the
   described runtime until an Issue and ADR change it. Compatibility
   pages describe current topology, not a freeze class.

## Consequences

Easier: one contract and one backlog. A later track is admitted by an
Issue and a later ADR, not by a freeze-class question.

Harder: "is this 1.0?" is no longer a product question. Operators read
ARCHITECTURE.md and the Issues. Compatibility pages keep a current
version tuple without calling it a 1.0 freeze.

No schema, policy, admit, GitHub write, Slack, or store change. ADR 0086
body stays as the historical freeze inventory. Independent self-hosting
stays author-validated until #146.

## Rejected alternatives

- Keep the freeze and only add post-1.0 issues: leaves freeze-as-identity
  in the contract, so every track still pays the 1.0 versus post-1.0 tax.
- Silently edit ADR 0086: destroys the historical freeze record and
  hides the supersession.
- Close #146: independent self-hosting is still the numbered-release
  quality bar, not this identity change.

## Validation and reversal

Validate by: this ADR merged; ARCHITECTURE.md no longer freezes a 1.0
core that excludes named tracks from the product; ROADMAP.md,
docs/README.md, docs/supported-topology.md, and docs/compatibility.md
describe current topology and sequencing; `scripts/adr-index --check`
and `python3 scripts/check-docs.py` clean; #146, #145, and #143 still
open.

Reverse with a later ADR that restores freeze-as-identity. No data
migration.
